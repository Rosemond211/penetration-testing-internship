# penetration-testing-internship
Penetration testing internship practical work and documentation for Days 1-6

## Days 1-3 Submission

This repository contains my practical work and learning evidence from Days 1-3 of the Penetration Testing Internship.

## Day 1: Networking

During Day 1, I learned the networking concepts that are important for penetration testing, including IP addresses, ports, TCP, UDP, DNS, HTTP/HTTPS and routing.

I practiced using Linux networking commands such as:

- `ip addr`
- `ip route`
- `ss -tuln`
- `nslookup`
- `curl -I`

I also created a basic network diagram and documented the command results and observations.

## Day 2: Linux

During Day 2, I practiced using the Linux terminal for security-related tasks.

I worked with:

- File and directory management
- Linux permissions
- `chmod`
- `grep`
- Process inspection with `ps aux`
- Network socket inspection with `ss -tuln`
- HTTP requests with `curl`
- Bash scripting

I also created a `system_snapshot.sh` script that records system information such as the current user, hostname, date, IP addresses and routing table.

## Day 3: Penetration Testing Foundations

During Day 3, I learned the basic penetration testing methodology and why authorization and scope are important.

I studied the major stages of a penetration test:

1. Scope and Rules
2. Reconnaissance
3. Enumeration
4. Vulnerability Analysis
5. Controlled Exploitation
6. Post-Exploitation / Impact Validation
7. Evidence and Cleanup
8. Reporting

I also created a mock penetration testing scope, classified different testing scenarios, created a security finding template and wrote an ethics reflection.

I completed practical learning through the TryHackMe Pentesting Fundamentals room and recorded notes and completion evidence.

## What I Still Find Difficult

I am still developing confidence with some penetration testing concepts and practical security tools. In particular, I need more practice with vulnerability analysis, enumeration and understanding how different security tools are used during an authorized assessment.

I also need more hands-on practice connecting observations from a target to a specific security finding and explaining the evidence and impact clearly.

## Safety and Authorization

All active security testing in this submission is limited to my own environment or explicitly authorized training platforms and lab targets.
